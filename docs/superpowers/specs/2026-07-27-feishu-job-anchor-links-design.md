# 飞书 Portfolio 岗位锚点链接设计

## 目标

在固定正式招聘文档
`https://zhenfund.feishu.cn/wiki/RTWjwVZjri4uCUk0J8wcn2K3n6d`
中，让 `Portfolio开放岗位汇总` 下的每条岗位 Bullet 都链接到
`岗位JD整理` 下同一公司的对应岗位标题。

功能同时覆盖：

1. 以后通过招聘 JD 发布助手新建或追加的岗位；
2. 正式文档中现有但尚未链接、链接错误或链接已失效的岗位。

Boss 直聘、脉脉、单岗位解析、公司官网链接和既有飞书模板结构保持不变。

## 已验证的链接模型

飞书岗位标题的文档内跳转地址是：

```text
<正式文档 URL>#<岗位标题 block_id>
```

正式文档中 CoFANCY 可糖的“品牌设计”标题当前可由以下地址定位：

```text
https://zhenfund.feishu.cn/wiki/RTWjwVZjri4uCUk0J8wcn2K3n6d#RzVZdfII4odibZxouyzcVxKln7c
```

因此插件不需要模拟“复制选区链接”、`Command + K`、剪贴板或飞书网页菜单。

## 核心数据模型

### 文档检查结果

现有 `inspectRecruitingDocument` 继续返回公司与岗位结构，并为 Portfolio 岗位增加：

- `location`
- `employment`
- `elements`：原始富文本元素的安全深拷贝
- `linkUrl`：整条岗位文字当前唯一且一致的链接；缺失、混合或不一致时为空

岗位 JD 继续提供岗位标题的 `blockId`、岗位名、地点和招聘类型。

### 唯一匹配键

岗位匹配使用以下复合键：

```text
normalize(companyName)
+ normalize(jobTitle)
+ normalize(location)
+ normalize(employment)
```

归一化沿用 `normalizeForMatch`，兼容全半角分隔符、空格和破折号。
岗位序号不参与匹配，因为追加岗位会改变序号语境，而岗位标题、地点和招聘类型才是
Portfolio 与 JD 的共同字段。

任一公司或岗位不能唯一匹配时，计划整体不可执行。第一版不猜测、不跳过歧义项、
不对安全子集做部分写入。

## 新岗位写入流程

现有写入顺序保持：

1. 读取正式文档并生成写入计划；
2. 写入岗位 JD；
3. 回读并校验岗位 JD；
4. 从回读结果中取得本次岗位标题的真实 `blockId`；
5. 生成正式文档锚点链接；
6. 渲染带链接的 Portfolio 岗位 Bullet；
7. 写入 Portfolio；
8. 回读并校验岗位文字、位置及链接目标。

`resume-new-company` 同样从已存在且完全匹配的 JD 岗位标题取得锚点，再补写
Portfolio，不重复创建 JD。

公司名称仍只使用公司官网链接；岗位链接始终覆盖整条
`岗位名｜地点｜招聘类型`。

如果在 JD 回读后无法唯一取得本次岗位标题块，流程在 Portfolio 写入前停止。

## 历史岗位补链

### 只读计划

新增独立的岗位链接维护计划：

1. 读取正式文档当前版本；
2. 遍历 Portfolio 公司和岗位；
3. 在 JD 区按复合键查找唯一岗位标题；
4. 生成期望锚点；
5. 分类为：
   - 已正确链接；
   - 缺少链接；
   - 链接错误或失效；
   - 无法匹配；
   - 匹配不唯一；
6. 返回不包含文档 ID、块 ID、原始元素或内部链接的公开预览。

公开预览只显示文档版本、总岗位数、已正确数量、待更新数量和按公司/岗位列出的
待更新项或错误。

### 写入

用户确认后：

1. 重新读取正式文档；
2. 要求当前版本与预览版本一致；
3. 重新生成并验证同一份安全计划；
4. 使用飞书 `blocks/batch_update` 的 `update_text_elements` 原位更新岗位 Bullet；
5. 保留每个原始 `text_run` 的内容和样式，只将其 `link.url` 设置为期望锚点；
6. 回读并要求所有岗位链接正确且待更新数为零。

单次计划最多更新 200 个块，以满足批量更新接口约束；超过时停止并提示拆分处理，
不自动进行多批次部分写入。

### 富文本安全

- 只接受完全由 `text_run` 组成的 Portfolio 岗位 Bullet；
- 每个 `text_run` 保留原内容和除 `link` 外的样式；
- 整条岗位的所有 `text_run` 写入同一个目标链接；
- 不删除或重建原岗位块，避免改变块 ID、评论和相邻结构；
- 不修改公司官网链接、岗位 JD 标题或引用块。

## 错误与幂等

- 文档版本变化：停止并要求重新检查；
- 公司或岗位不唯一：停止，不写入；
- API 明确拒绝：不重试；
- API 网络结果不明：只回读一次；若回读证明全部完成则成功，否则返回未知状态；
- API 接受写入但回读失败：返回未知状态，提示不要重复提交；
- 重复执行只读计划时，已正确链接的岗位不会再次进入更新列表；
- 完成后再运行计划应显示待更新数量为零。

## 界面

正常新增岗位流程不增加步骤。用户仍然：

1. 授权飞书；
2. 粘贴并解析；
3. 生成写入计划；
4. 确认写入。

在飞书授权面板增加一个默认收起的“维护已有岗位链接”区域，避免干扰日常初次操作：

- `检查岗位链接`：只读扫描并显示计划；
- `确认补全 N 个岗位链接`：仅在计划可执行且 `N > 0` 时出现；
- `全部岗位链接已正确`：无需写入时显示；
- 失败或未知状态显示安全诊断和人工检查建议。

## 权限与隐私

沿用现有权限：

- `wiki:wiki:readonly`
- `docx:document:readonly`
- `docx:document:write_only`

不增加 Chrome/Edge host 权限、剪贴板权限、`debugger` 权限或 macOS 辅助功能权限。
同事继续使用各自的 `user_access_token`，并且必须拥有正式文档编辑权限。

侧栏消息不得返回：

- access token 或 App Secret；
- Docx 文档 ID；
- block ID；
- 原始富文本元素；
- 内部锚点 URL；
- 未经白名单处理的 API 错误正文。

## 验收

### 自动化

- 锚点 URL 使用固定正式文档和岗位标题 `blockId`；
- 新公司、追加岗位、恢复模式创建的 Portfolio Bullet 均带正确链接；
- Portfolio 回读校验缺失链接或错误链接时失败；
- 历史补链正确识别已链接、缺失、错误、歧义和超过 200 项；
- 批量更新保留文本与样式，只替换链接；
- 版本冲突、API 拒绝、网络未知和回读失败状态准确；
- 公开消息不泄露 ID、元素或链接；
- Boss/脉脉完整回归测试通过；
- `npm run build` 成功。

### 正式文档人工验收

1. 只读扫描正式文档，确认预览数量与人工抽查一致；
2. 先仅补全 CoFANCY 可糖两个岗位并确认跳转正确；
3. 再执行全量历史补链；
4. 新增一个岗位，确认 Portfolio 新岗位创建时已自动带锚点；
5. 再次扫描显示待更新数量为零。
