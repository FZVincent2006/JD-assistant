# Outlook 正文与简历附件飞书推送设计

## 目标

在现有 Outlook 网页邮件列表扫描、基线、去重和重试机制之上，增加可选的增强投递模式：

1. 继续由 `partner.outlook.cn` 内容脚本检测目标文件夹中的新邮件。
2. 对已判定为新个人投递的邮件，通过 GUI 打开对应邮件并读取阅读窗格。
3. 使用当前 Outlook 网页登录状态下载 PDF、DOC、DOCX 简历。
4. 通过飞书自建应用机器人发送正文卡片和简历文件。
5. 保留旧的自定义机器人 Webhook 主题提醒作为兼容模式。

## 身份与边界

- 不调用 Microsoft Graph，不需要 Client ID、Tenant ID、邮箱密码或 Outlook OAuth 凭证。
- Outlook 内容脚本只运行于固定的 `https://partner.outlook.cn/mail/*`。
- 下载地址只接受同源 HTTPS 或当前页面生成的 Blob URL。
- 飞书短期 `tenant_access_token` 由本机 Native Messaging 助手使用 Keychain 中既有 App Secret 获取；Secret 不进入扩展进程、源码或日志。
- 飞书应用需开启机器人能力、消息发送和文件资源权限，并加入目标私密群。

## 数据流

```text
Outlook 邮件列表扫描
→ 新邮件去重键
→ 按 data-convid 定位并点击唯一邮件行
→ 等待阅读窗格并核对主题
→ 提取可见正文和附件下载入口
→ 使用当前网页会话下载白名单简历到内存
→ 飞书正文卡片
→ 上传并发送每份简历
→ 持久化完成部件并标记邮件已投递
```

队列不保存正文、附件名称、下载地址或附件内容，只保存邮件行页面标识和发送完成部件。每完成
正文卡片或一份附件消息后立即保存进度，重试时跳过已经成功的部件。

## 限制

- 仅发送 PDF、DOC、DOCX；忽略内嵌图片和其他文件。
- 飞书单文件上限 30 MB；单封邮件附件总量上限 60 MB。
- 正文最多 12,000 字，超出时明确标记截断。
- 邮件行消失、阅读窗格主题不匹配、附件没有安全下载入口时失败或跳过，不猜测另一封邮件。
- 增强模式会通过 GUI 打开新邮件，因此可能把邮件标记为已读。
- Outlook 网页结构升级后可能需要维护选择器；标签页必须保持登录并打开目标文件夹。
- 只支持固定邮箱 `recruiting@zhenfund.com` 和固定文件夹 `个人投递（需提醒）`。

## 隐私与日志

- 正文、附件下载地址和附件二进制只存在于一次投递调用的内存中。
- 诊断事件只记录状态、数量和脱敏错误码。
- 目标群必须是仅包含获准处理招聘数据人员的私密群。
