# 飞书历史岗位链接安全部分执行设计

## 背景

正式招聘文档包含长期积累的历史格式差异，包括旧链接、公司名称差异、
岗位字段顺序差异、重复岗位和字段不完整。当前实现只要发现任意一条异常，
就把整个岗位链接计划标记为不可执行，导致本来可以唯一匹配的岗位也无法补链。

## 方案比较

1. **安全部分执行（采用）**：只计划能够按公司和岗位字段唯一匹配、且当前没有
   链接的岗位；其他岗位保持原样并列入人工项。覆盖范围最大，同时不降低安全性。
2. **按公司阻断**：一个公司出现一条异常就跳过整家公司。实现简单，但会继续阻塞
   同公司内大量可以安全补链的岗位。
3. **模糊匹配并自动覆盖**：根据标题相似度猜测目标。覆盖范围最大，但可能把岗位
   链到错误位置，不符合“正确填入优先”的核心要求，因此不采用。

## 计划模型

扫描结果区分两种问题：

- `errors`：阻止整批执行的系统性错误，例如文档版本无效、待更新数量超过单批上限、
  无法建立可靠的文档块模型。
- `issues`：仅影响单个公司或岗位的历史数据问题，例如公司无法唯一匹配、岗位无法
  唯一匹配、字段不完整、已有未知链接、混合链接或无法安全保留的富文本。

只要没有 `errors`，计划就是可执行计划。计划同时返回：

- 文档版本、总岗位数和已正确链接数；
- 可以安全更新的 `updates`；
- 人工项 `issues` 及数量；
- 按公司分组后的可更新岗位，供用户选择。

如果没有安全更新但存在人工项，界面显示“没有可安全自动补全的岗位”，不得显示
“全部岗位链接已正确”。

## 匹配与写入安全边界

- 公司仍只允许标准化名称后的唯一精确匹配。
- 岗位仍只允许岗位名、地点和招聘类型标准化后的唯一精确匹配。
- 不增加标题相似度、别名或字段调换推断。
- 已有标准块链接或飞书选区链接保持不变并计为已正确。
- 已有外部链接、未知文档链接或混合链接保持不变，列入人工项。
- 无法匹配、重复或字段不完整的公司和岗位保持不变，列入人工项。
- 写入前重新读取文档并按最新版本重建计划；只允许写入当前计划中仍然存在的
  已选安全更新。
- 写入后回读时，未解决的人工项不导致校验失败；所选安全更新仍存在、岗位总数变化
  或文档结构异常才导致失败。

## 界面与操作流程

“维护已有岗位链接”区域明确展示三步：

1. 点击“检查岗位链接”（只读）。
2. 在“可安全补全”列表中勾选公司。
3. 点击“确认补全已选 N 个岗位链接”，并在确认框中再次确认。

扫描结果卡片显示：

- 可安全补全数量；
- 已正确数量；
- 需人工检查数量；
- 可安全补全的公司复选框；
- 默认收起的“需人工检查”列表及具体原因。

人工项永远没有自动写入按钮。用户可以分批选择公司；首次仍建议选择一家验收。

## 测试与验收

- 单元测试覆盖：安全更新与异常并存、未知已有链接、公司不匹配、岗位不匹配、
  重复或不完整岗位、零安全更新但存在人工项、真正的全正确状态、批量上限。
- 写入测试覆盖：只写所选安全更新；人工项不阻断写入和回读；文档版本变化继续阻断；
  所选更新在写入前消失时停止。
- UI 测试覆盖：结果数量、公司选择、禁用状态、人工项文案和“全部正确”判定。
- 完整回归必须继续覆盖 Boss、脉脉、Outlook、飞书新增公司与追加岗位流程。
